## Scoring rules (T-013.2), pre-registered

**Matching.** Before any status is read, every codebook construct (supported or not) is mapped from its definition alone to one planted trait with an orientation (`same` or `inverse`), or to none. Two matchers: me, and a fresh Codex through `invoke.execute` given only the definitions and the matrix's behaviour column (no statuses, no record). A mapping counts only where both agree; disagreements are listed and count as none. A construct maps to at most one trait. Several constructs may map to one trait (a split).

**Reading a trait in an era**, from the agreed mapping and the harness's per-era construct statuses (`supported`, and contradicted as `temporal.py` defines it):

| Any `same` supported | Any `inverse` supported | Reading |
|---|---|---|
| yes | no | observed |
| no | yes | contradicted |
| yes | yes | conflict: no credit either way |
| no | no | contradicted if the trait has at least one `same` construct and every one is contradicted; otherwise undecided |

A planted-positive trait (T1–T10) with no agreed construct is unrecovered: each of its recovery checks (stable, transition, held, one-era) fails and stays in its denominator. The never-shown rows (T0, N1) pass absence when they have no agreed `same` construct supported in any era, mapped or not. An `inverse` construct's absent or insufficient verdict never makes the trait observed. A transition is at the keyed boundary when the era before it and the era after it read the keyed pair exactly (fade: observed then contradicted; emergence: contradicted then observed). The harness's own temporal read of each matched construct is reported beside these readings. `score.py` carries hand-asserted cases for every row of the table, an unmapped planted-positive trait (fails recovery), an unmapped silent trait (passes absence), a supported `same` construct for T0 (fails absence), an inverse-only trait and a split trait, plus the fake-run integration check.

| Check | Measure | Pass |
|---|---|---|
| Run | `prepare` passes calibration (exit 0); every later stage completes; `tests/recompute.py` matches the report | must |
| Arms | extraction exit 1 is recorded as the named arm failing its gate | reported |
| Zoning | R + X plants removed or mixed; K plants kept; by class | R+X ≥ 95 % (≤ 2 of 42); K ≥ 80 % |
| Traps | all three trap sentences absent from the substrate | must; raw-rating citations and supported verdicts reported |
| Future-blind | no sentinel in any discovery input or output for an earlier era | must |
| Stable | T1, T2, T3, T10 each observed in ≥ 5 of 6 eras | ≥ 3 of 4 |
| Transitions | T4, T5, T6, T7 change at the keyed boundary exactly | ≥ 3 of 4 |
| Held | T8 observed e1–e2, held e3–e6, Now held | reported |
| One-era | T9 emergence e4→e5, fade e5→e6 | reported |
| Absence | no supported `same` construct for T0 or N1 | must |
| Three-way | firm rows equal the key | ≥ 4 of 6 |
| Unkeyed | supported constructs mapped to none, with definitions | reported |

Results are reported per check and per trait, not only as pass counts. A miss is data about the method; neither record nor key changes after sealing, and every denominator is fixed. Both matchers' decisions and the agreed mapping are frozen (hashed into NOTES) before any construct status is read. Where the sealed checker evidence shows a chapter failed to realise its brief, the miss is annotated as a possible authoring error; an annotation never turns a miss into a pass.
